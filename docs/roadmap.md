# 확장 로드맵 — 한 번 작성, 세 사용자에게 재활용

목표: 구직자는 원본 포트폴리오 하나만 쓰고, 기업은 핵심만 보고, 담당자는 기록으로 판단한다. 누구도 같은 내용을 두 번 입력하지 않는다.

## 구현 완료 (이번 프로젝트)

| 단계 | 기능 | AI 역할 | 기술 요소 |
|---|---|---|---|
| 구직자 | 참여 이력·경험 → 활동 정리·역량 문장·포트폴리오 초안, 공고 추천 | 문장 생성 (근거 없는 수치·지원금·연령 차단) | 생성형 AI |
| 기업 | 공고 점검, 지원자 배지(사유·연령 비공개), 근로계약 점검 | 결과 설명 | 규칙엔진 + 생성형 AI |
| 기업 | 사업자번호 조회 → 업종·임금체불·체납 자동 점검 | — | 공공데이터(합성, API 형식 동일) |
| 기업 | **채용 확정 서류(근로계약서·사업자등록증) 한 번 첨부 → 판독·점검·공고 대조** | 항목 판독만 | **멀티모달 AI** |
| 기업 | 월별 급여명세서·이체확인증 판독 → 그 달 기준 점검 | 항목 판독만 | **멀티모달 AI** |
| 담당자 | 신청 건에 참여 이력 근거·계약 점검·서류 기록이 자동으로 모임 | — | **자동화 워크플로우** |

## 다음 단계 (개방성·확장성)

| 순서 | 기능 | 사용자 | AI 활용 | 기술 요소 |
|---|---|---|---|---|
| 1 | **추천 공고 맞춤 포트폴리오** — 원본 하나로 공고별 강조점·지원 동기 재구성 + "요구 역량 ↔ 내 경험 근거" 대응표 | 구직자 | 재구성·대응표 생성 (없는 경험은 guard 차단) | 생성형 AI |
| 2 | **빈칸 질문** — 공고가 요구하는데 원본에 없는 역량을 1~2개 질문 → 답이 원본에 쌓여 다음 공고에도 재활용 | 구직자 | 질문 생성 | 생성형 AI + Long-term Memory |
| 3 | **기업 핵심 카드** — 공고 요구 역량별 근거 1줄 + 출처(훈련·프로젝트·자격) 표시 | 기업 | 근거 문장 선택 (과장 불가) | 생성형 AI |
| 4 | **공고·계약서 불일치 자동 표시** 고도화 — 수당·근로시간 단위까지 대조 | 기업·담당자 | — | 규칙엔진 |
| 5 | **담당자 요약** — "이 건은 ○○ 항목만 확인하면 됨" + 보완 요청 안내문 자동 작성 | 담당자 | 요약·안내문 생성 (판정은 규칙) | 생성형 AI |
| 6 | **AI 판독 정확도 표** — 합성 양식별 판독값 vs 정답표 비교 | 운영 | 평가 | 멀티모달 |
| 7 | **지원제도 Q&A** — 공개 지침을 검색해 근거 문단을 붙여 답변 | 구직자·기업 | RAG | RAG |
| 8 | **서류 챙김 에이전트** — 빠진 달·불일치 탐지 → 기업별 요청문 → 알림 발송 | 기업·담당자 | Agent | AI Agent + 자동화 |
| 9 | **실제 공공데이터 연동** — 고용24 채용정보·임금체불 API(승인 후 키만 교체), 국세청 사업자 상태조회, 국민연금 사업장(업종·규모) | 전체 | — | 공공데이터 |
| 10 | 고용24 회원·행정 시스템 연계, 참여 이력 자동 연동, 성과 통계 환류 | 전체 | — | 시스템 연계 |

설계 원칙은 유지됩니다: AI는 읽기·설명·재구성만, 판단은 규칙엔진, 최종 결정은 사람. 개인정보는 동의 범위에서만, 참여 사업명·연령은 기업에 비공개.
