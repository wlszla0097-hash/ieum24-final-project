# 확장 로드맵 — 한 번 작성, 세 사용자에게 재활용

목표: 구직자는 원본 포트폴리오 하나만 쓰고, 기업은 핵심만 보고, 담당자는 기록으로 판단한다. 누구도 같은 내용을 두 번 입력하지 않는다.

## 구현 완료 (이번 프로젝트)

| 단계 | 기능 | AI 역할 | 기술 요소 |
|---|---|---|---|
| 구직자 | 참여 이력·경험 → 활동 정리·역량 문장·포트폴리오 초안, 공고 추천 | 문장 생성 (근거 없는 수치·지원금·연령 차단) | 생성형 AI |
| 기업 | 공고 점검, 지원자 배지(사유·연령 비공개), 근로계약 점검 | 결과 설명 | 규칙엔진 + 생성형 AI |
| 기업 | 사업자번호 조회 → 업종·임금체불·체납 자동 점검 | — | 공공데이터(합성, API 형식 동일) |

| 담당자 | 신청 건에 참여 이력 근거·계약 점검·서명된 계약서·월별 대조 기록이 자동으로 모임 | — | **자동화 워크플로우** |
| 기업 | **최저임금 미달 근로계약서 저장 차단** — 계산식·최저임금법 근거 제시 (지원제도와 무관) | — | 규칙엔진 |

## 우선 확장: 취업애로청년 요건 전체 반영 (실무 기준)

**왜**: 지금은 국민취업지원제도 참여 후 최초 취업·청년도전지원사업 수료 2가지만 판단합니다. 실제 운영 현장에서는 **4개월 이상 실업**, **최종학교 졸업 후 고용보험 가입기간 12개월 미만**처럼 고용보험 이력만으로 확인되는 요건으로 지원대상이 되는 청년이 훨씬 많습니다. 이 요건을 넣으면 같은 서비스로 **훨씬 많은 청년 구직자**에게 '지원제도 활용 가능'을 알려 줄 수 있습니다.

**어떻게** (취업애로청년, 수도권 기업 — 아래 중 1개):

| 요건 | 확인 방법 | 지금 → 확장 |
|---|---|---|
| 4개월 이상 실업 상태 | 마지막 고용보험 상실일 ↔ 채용일 계산 | 없음 → 날짜로 자동 계산 |
| 고졸 이하 학력 | 최종학력 선택 | 없음 → 선택 |
| 최종학교 졸업 후 고용보험 가입기간 12개월 미만 | 졸업일 + 졸업 후 가입 개월 | 없음 → 날짜·개월로 자동 계산 |
| 국민취업지원제도 참여·미래내일일경험·일학습병행 수료 후 최초 취업 | 참여·수료일 ↔ 고용보험 취득일 | 국취만 → 3개 사업 |
| 청년도전지원사업 수료 | 수료일 | ✅ 구현 |
| 대량고용변동 사업장 이직·자영업 폐업 후 최초 취업, 고용촉진장려금 대상 | 본인 체크 → 고용센터 확인 | 없음 → 체크리스트 |
| 자립준비·보호연장청년, 북한이탈청년 | 본인 체크(민감정보 — 기업에는 사유 비공개) | 없음 → 체크리스트 |
| 제외: 재학·휴학, 타 사업장 고용보험 가입 중, 사업자등록 | 본인 체크 | 없음 → 배지 미표시 + 이유 안내 |

- 배지 사유에 계산 근거를 표시 (예: "졸업 후 고용보험 가입 8개월 — 12개월 미만")
- 1단계는 본인 입력, 고용24 연동 후에는 **고용보험 이력 자동 조회**로 입력 없이 판단 (아래 9·10)
- 설계 원칙 동일: 판단은 규칙엔진, 사유·연령은 기업 비공개, 최종 확인은 고용센터
- 기준: 2026년 청년일자리도약장려금 사업운영 지침('26.4월 개정) — 반영 시 조항·문구 대조

## 다음 단계 (개방성·확장성)

| 순서 | 기능 | 사용자 | AI 활용 | 기술 요소 |
|---|---|---|---|---|
| 1 | **추천 공고 맞춤 포트폴리오** — 원본 하나로 공고별 강조점·지원 동기 재구성 + "요구 역량 ↔ 내 경험 근거" 대응표 | 구직자 | 재구성·대응표 생성 (없는 경험은 guard 차단) | 생성형 AI |
| 2 | **빈칸 질문** — 공고가 요구하는데 원본에 없는 역량을 1~2개 질문 → 답이 원본에 쌓여 다음 공고에도 재활용 | 구직자 | 질문 생성 | 생성형 AI + Long-term Memory |
| 3 | **기업 핵심 카드** — 공고 요구 역량별 근거 1줄 + 출처(훈련·프로젝트·자격) 표시 | 기업 | 근거 문장 선택 (과장 불가) | 생성형 AI |
| 4 | **공고·계약서 불일치 자동 표시** 고도화 — 수당·근로시간 단위까지 대조 | 기업·담당자 | — | 규칙엔진 |
| 5 | **담당자 요약** — "이 건은 ○○ 항목만 확인하면 됨" + 보완 요청 안내문 자동 작성 | 담당자 | 요약·안내문 생성 (판정은 규칙) | 생성형 AI |
| 6 | **AI 판독 정확도 표** — 합성 양식별 판독값 vs 정답표 비교 | 운영 | 평가 | 멀티모달 |
| 7 | **지원제도 Q&A** — 공개 지침을 검색해 근거 문단을 붙여 답변 | 구직자·기업 | RAG | RAG |
| 8 | **서류 챙김 에이전트** — 빠진 달·불일치 탐지 → 기업별 요청문 → 알림 발송 | 기업·담당자 | Agent | AI Agent + 자동화 |
| 9 | **실제 공공데이터 연동** — 고용24 채용정보·임금체불 API(승인 후 키만 교체), 국세청 사업자 상태조회, 국민연금 사업장(업종·규모) | 전체 | — | 공공데이터 |
| 10 | 고용24 회원·행정 시스템 연계(기업·구직자 로그인 — 지금의 기업 선택 화면 자리), 참여 이력 자동 연동, 성과 통계 환류 | 전체 | — | 시스템 연계 |
| 11 | **전자서명 고도화** — 본인 확인(간편인증)·위변조 방지(서명 시점 문서 해시) 후 계약서 PDF 교부 | 기업·근로자 | — | 전자서명 |
| 12 | **이체 내역 직접 확인** — 오픈뱅킹 등 기관 연계로 이체확인증 업로드 없이 지급 사실 확인 (지금은 기업이 은행 발급 확인증을 올림) | 기업·담당자 | — | 금융 API |

설계 원칙은 유지됩니다: AI는 읽기·설명·재구성만, 판단은 규칙엔진, 최종 결정은 사람. 개인정보는 동의 범위에서만, 참여 사업명·연령은 기업에 비공개.
